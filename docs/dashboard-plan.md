# MES 대시보드 전환 계획

## 목적

- 3D 공정 시뮬레이션 앱을 **실제 제조회사에서 쓸 법한 MES 대시보드**로 바꾼다.
- 포트폴리오·학습용 데모다. 데이터는 브라우저 안의 시뮬레이션 엔진이 만드는 가상 데이터로 충분하다.
- 핵심은 대시보드를 만들면서 **MES에 어떤 기능이 있는지, 제조 KPI와 운영 개념이 무엇인지** 익히는 것이다. 제조회사 개발자로 일하기 위해 기본으로 알아야 할 개념을 페이지마다 하나씩 다룬다.

## 결정 사항

| 항목 | 결정 |
|---|---|
| 데이터 | 브라우저 안의 시뮬레이션 엔진(`sim/engine.ts`). 백엔드 없음 |
| 사용 화면 | 관리자 모드(PC, 조회·조작) + 관제판 모드(벽면 TV, 조작 없음) |
| 3D 화면 | 생산 현황 페이지의 "라인 현황" 위젯으로 유지 |
| 기존 시나리오(S1~S3) | "교육 모드" 메뉴로 남긴다 |
| 차트 | ECharts |
| 라우팅 | vue-router |

## 페이지 구성 (MES 기능 기준)

| # | 페이지 | MES 기능 | 화면 내용 | 익히는 개념 |
|---|---|---|---|---|
| 1 | 생산 현황 (메인) | 생산 모니터링 | 계획 대비 실적·UPH·OEE·양품률·WIP 카드, 시간대별 생산 추이, 3D 라인 위젯, 최근 알람 | 계획 대비 실적, UPH, WIP, 리드타임, Little의 법칙 |
| 2 | 작업지시 관리 | 작업지시/생산 실행 | 작업지시 목록(상태 필터), 상태 흐름, 진척률, 하달·보류·우선순위 조작 | 작업지시 생명주기, 라우팅, 디스패칭 |
| 3 | 설비 관리 | 설비 관리/보전 | 설비 상태판, OEE 분해, 비가동 사유 파레토, 센서 추이, 예방정비 | OEE, MTBF/MTTR, 계획·비계획 정지, 예지보전 |
| 4 | 품질 관리 | 품질/추적성 | 불량률 추이, 불량 유형 파레토, 제품 이력 조회 | 양품률, FPY, 파레토 분석, LOT 추적성 |
| 5 | 자재/재고 | 자재 관리 | 재고 수준과 안전재고, BOM 소요량, 발주 현황 | BOM, 안전재고, 조달 리드타임 |
| 6 | 실적 리포트 | 성과 분석 | 일/교대별 실적표, KPI 요약 | 교대(Shift), 일일 생산 보고 |
| - | 교육 모드 | - | 기존 3D 시나리오(S1~S3, 자유 체험) | 병목, 예지보전, 자재 부족 대응 |

각 페이지에는 "개념 설명" 패널을 붙여 화면을 쓰면서 개념을 바로 확인할 수 있게 한다.

## 엔진에 추가가 필요할 수 있는 데이터

해당 페이지를 만들 때 코드를 확인하고 범위를 정한다.

- 생산 계획 목표량 (계획 대비 실적)
- 교대 개념 (교대별 실적)
- 불량 유형 코드 (불량 파레토)
- 비가동 사유 코드 (비가동 파레토)

## 시뮬 엔진 공유 규칙

- 대시보드의 모든 페이지는 같은 엔진(자유 체험 공장)을 본다. 앱을 열면 바로 돌아간다.
- 교육 모드에서 시나리오를 고르면 엔진이 시나리오용으로 바뀐다. 교육 모드를 나와 대시보드로 돌아오면 자유 체험 공장을 처음부터 다시 돌린다.

## 브랜치 전략

Git Flow를 줄인 형태를 쓴다. 저장소: https://github.com/popcorn0125/mes-study

| 브랜치 | 용도 |
|---|---|
| `main` | 배포용. `dev`가 안정되면 PR로 합치고 태그(`v0.1.0` 등)를 붙인다 |
| `dev` | 개발 통합용. 기능 브랜치를 PR로 합친다 |
| `feature/<모듈 이름>` | 기능(단계) 단위 개발. `dev`에서 갈라져 PR로 `dev`에 합친다 |

- `feature/*` → `dev` 합치기는 사용자가 GitHub PR에서 직접 한다.
- `main`과 `dev`는 GitHub 브랜치 보호로 직접 push를 막는 것을 권장한다.
